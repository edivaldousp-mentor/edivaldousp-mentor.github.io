Módulo 0

O problema, e o que existe de real

A pergunta: dado o que se sabe do perfil socioeconômico de uma pessoa — idade, renda, escolaridade, ocupação, região — qual a probabilidade de ela ser apostadora?

Este é o primeiro modelo do portfólio. O objetivo não é acertar o número: é mostrar o método completo, do desenho da amostra ao ponto de corte, com cada decisão explicitada.

As âncoras reais

A base é sintética, mas não é inventada. As prevalências foram calibradas a três fontes públicas — o que faz a diferença entre um exercício de brinquedo e um estudo defensável.

FonteDataAmostraO que diz

Duas ressalvas metodológicas que vieram junto e mudaram o desenho:

1. 13% e 36% não se contradizem — medem coisas diferentes. "Apostou nos últimos 30 dias" é uma pergunta; "faz apostas" é outra. A definição do alvo muda a prevalência em quase três vezes. Adotei a do DataSenado (13%) por ser a mais precisa e a de maior amostra.

2. Composição não é prevalência. O DataSenado diz que 62% dos apostadores são homens — isso é composição. O PoderData diz que 43% dos homens apostam — isso é prevalência. Confundir as duas é erro clássico. Para calibrar a base eu precisava de prevalência por segmento, e a derivei da composição mais os marginais populacionais.

Aviso que vale repetir: os dados desta base são fictícios. Nenhuma pessoa real foi usada, e o modelo não deve ser aplicado a decisões sobre pessoas reais. O uso pretendido é demonstrar técnica.

Módulo 1

A base sintética: como foi construída

Uma base sintética bem feita tem uma propriedade que uma base real não tem: existe uma verdade de terreno. Eu sei exatamente qual logit gerou o alvo, então posso perguntar se o modelo recuperou o que estava lá.

O processo tem quatro passos:

  1. Sortear a população a partir de marginais aproximadas do Brasil adulto (sexo, faixa etária, escolaridade, região, ocupação).
  2. Derivar as variáveis dependentes com estrutura realista — renda como log-normal deslocada por escolaridade, ocupação, idade e região; benefício social com probabilidade caindo com a renda; ocupação condicionada à idade.
  3. Aplicar um logit conhecido, com coeficientes escolhidos para reproduzir as prevalências publicadas.
  4. Calibrar o intercepto por bisseção até a prevalência média bater exatamente 13%.
Python
def calibra_intercepto(z, prev_alvo):
    """Acha 'a' tal que a media de sigmoide(a + z) = prev_alvo."""
    lo, hi = -12.0, 12.0
    for _ in range(200):
        meio = (lo + hi) / 2
        p = 1 / (1 + np.exp(-(meio + z)))
        if p.mean() > prev_alvo:
            hi = meio
        else:
            lo = meio
    return (lo + hi) / 2

z = logito(df)                       # soma dos coeficientes por faixa
a = calibra_intercepto(z, 0.13)      # 13% — ancora DataSenado
p = 1 / (1 + np.exp(-(a + z)))
df["apostador"] = (rng.random(len(df)) < p).astype(int)

Módulo 2

WOE e Information Value

Antes de qualquer regressão, cada variável é analisada sozinha. O WOE (peso da evidência) transforma cada faixa num número que diz o quanto ela empurra para o evento; o IV resume, num único valor, o poder preditivo da variável inteira.

A convenção importa e varia por autor. A adotada aqui, declarada de propósito:

Fórmula
WOE = ln( P(faixa | apostador) / P(faixa | nao apostador) )

Com essa definição, WOE positivo = faixa com mais apostadores que a média, e coeficiente positivo na regressão significa "aumenta a propensão". Na literatura de crédito é comum o inverso (ln(bom/mau)); as duas funcionam, desde que você não misture.

Python
def tabela_woe(df, var, alvo="apostador"):
    g = df.groupby(var)[alvo].agg(n="size", eventos="sum").reset_index()
    g["nao_eventos"] = g["n"] - g["eventos"]
    tot_e, tot_ne = g["eventos"].sum(), g["nao_eventos"].sum()
    g["taxa"] = g["eventos"] / g["n"]
    # a correcao de 0,5 evita log de zero em faixa sem evento
    g["dist_evento"]     = (g["eventos"]     + 0.5) / (tot_e  + 0.5 * len(g))
    g["dist_nao_evento"] = (g["nao_eventos"] + 0.5) / (tot_ne + 0.5 * len(g))
    g["woe"] = np.log(g["dist_evento"] / g["dist_nao_evento"])
    g["iv_parcial"] = (g["dist_evento"] - g["dist_nao_evento"]) * g["woe"]
    return g

Como ler: as três variáveis de gradiente — idade, renda e escolaridade — saem monotônicas, sem eu ter imposto isso. É o sinal de que o binning está bem feito. Se uma delas serrilhasse, o certo seria reagrupar as faixas antes de seguir, não deixar o modelo lidar com o ruído.

Módulo 3

Seleção: IV não basta

O IV avalia cada variável isolada. Duas variáveis podem ter IV alto e dizer a mesma coisa. Por isso o segundo filtro é de redundância.

Fator de inflação da variância (VIF)6 linhas

Regra prática: VIF acima de 5 preocupa, acima de 10 é multicolinearidade forte. O máximo aqui é 1,73.

A maior correlação entre as WOE é 0,551, entre renda e benefício social, e faz todo sentido: o benefício é concedido por faixa de renda, então uma quase contém a outra. Como o VIF ficou baixo e as duas mantiveram coeficiente significativo e sinal coerente, mantive as duas. Se o VIF tivesse passado de 5, o caminho seria clusterizar as variáveis correlacionadas e manter a de maior IV de cada grupo.

Módulo 4

A regressão logística

Seis variáveis, transformadas em WOE, entram numa logística sem regularização. Os erros-padrão vêm da matriz de informação de Fisher — não é preciso statsmodels para ter teste de significância:

Python
mod = LogisticRegression(C=np.inf, max_iter=2000).fit(Xtr, ytr)

# erro-padrao pela matriz de informacao: SE = raiz da diagonal de inv(X' W X)
Xd = np.column_stack([np.ones(len(Xtr)), Xtr.values])
p  = mod.predict_proba(Xtr)[:, 1]
W  = p * (1 - p)
cov = np.linalg.inv(Xd.T @ (Xd * W[:, None]))
se  = np.sqrt(np.diag(cov))

z = np.concatenate([mod.intercept_, mod.coef_[0]]) / se
p_valor = 2 * (1 - norm.cdf(np.abs(z)))

Um detalhe que vale conhecer: quando o WOE está bem construído, o coeficiente de cada variável tende a ficar próximo de 1. É uma consequência da matemática do WOE, não coincidência. Coeficiente muito acima de 1 sugere que aquela variável está compensando outra; muito abaixo, que ela é redundante com as demais. Aqui eles vão de 0,37 a 1,04 — faixa saudável.

Módulo 5

Do coeficiente ao ponto

Um coeficiente de 0,4565 sobre um WOE de −0,58 não significa nada para quem vai usar o modelo. O scorecard traduz isso em pontos que se somam.

A escala tem dois parâmetros que você escolhe:

  • PDO (points to double the odds) = 50. A cada 50 pontos a mais, a chance de a pessoa ser apostadora dobra.
  • Score base = 500, ancorado na prevalência da população (13%).
Fórmula
fator  = PDO / ln(2)                       = 72,1348
offset = 500 − fator × ln(odds da base)    = 636,6556

pontos da faixa = (offset + fator × intercepto) / n_variaveis
                + fator × coeficiente × WOE da faixa

Atenção a um ponto que confunde quem vem de crédito: aqui score maior = propensão maior. Em score de crédito é o contrário — score alto é cliente bom. Inverti de propósito porque "score de propensão" alto significando "mais propenso" é mais intuitivo, mas isso precisa estar escrito em letras garrafais na ficha do modelo, ou alguém vai ler ao contrário.

Módulo 7

Calibração, e o que a safra futura revelou

Ordenar bem não é o mesmo que acertar o nível. Um modelo pode colocar as pessoas na ordem certa e ainda assim errar a probabilidade de todas elas. Quem usa o score só para ranquear pode ignorar isso; quem usa o número — para dimensionar uma campanha, estimar volume — não pode.

No teste, o modelo está em cima da diagonal: previu 4,7% no decil mais baixo e observou 4,1%; previu 27,6% no mais alto e observou 27,8%. Brier de 0,1093.

Na safra futura, todos os pontos ficam acima da diagonal. O modelo prevê 13,75% na média, e a realidade é 15,87% — subestima em 2,1 pontos percentuais, sistematicamente.

O diagnóstico correto

Aqui está o achado do estudo, e ele é o tipo de coisa que separa uma validação superficial de uma boa:

IndicadorResultadoLeitura
AUC na safra futura0,6549 vs 0,6564 no testeA ordenação está intacta
PSI do score (treino × safra)0,0104A distribuição não se moveu
Média prevista vs observada13,75% vs 15,87%O nível deslocou

Discriminação preservada, distribuição estável, nível errado. Isso não é modelo quebrado — é modelo descalibrado. E a correção não é remodelar: é deslocar o intercepto.

Python
from scipy.optimize import brentq

logito_oot = np.log(oot["prob"] / (1 - oot["prob"]))
delta = brentq(
    lambda d: (1 / (1 + np.exp(-(logito_oot + d)))).mean() - y_oot.mean(), -3, 3
)
# delta = +0,1756  ->  equivale a +12,7 pontos no score
# Brier: 0,1286 -> 0,1281   |   AUC: 0,6549 (inalterado, como tem que ser)

Um deslocamento de +12,7 pontos no score corrige a safra inteira, sem tocar em nenhum coeficiente. O AUC não muda, e não poderia mudar, porque somar uma constante a todos os logitos não altera a ordem de ninguém.

Por que isso aconteceu: a safra foi gerada com população mais jovem e mais informal e com prevalência maior. O modelo capturou a parte explicada pelas variáveis; o resto do aumento é um efeito de época que nenhuma variável socioeconômica poderia prever — o mercado de apostas cresceu. É exatamente o caso em que se recalibra periodicamente e se mantém o modelo.

Módulo 8

O ponto de corte

O modelo entrega uma probabilidade contínua. O corte é o que transforma isso em decisão, e ele não é uma escolha estatística, é uma escolha de negócio. A estatística só mostra o que se ganha e o que se perde em cada opção.

As três curvas contam a história inteira. Conforme o corte sobe: a precisão melhora (quem você seleciona é cada vez mais provável de ser apostador), o recall piora (você deixa cada vez mais apostadores de fora) e o volume abordado despenca.

Os três cortes que eu levaria para a mesa

Corte 510 — o estatístico. É onde o KS é máximo (Youden 0,223), o ponto de maior separação entre as duas curvas acumuladas. Abordaria 32,8% da base, capturaria 52,2% dos apostadores, com precisão de 20,8% e lift de 1,59. Use quando não há uma assimetria clara de custo entre errar para mais e errar para menos.

Corte 550 — o de foco. Abordaria 9,0% da base, com precisão de 28,9% e lift de 2,21 — o dobro da média. Em compensação captura só 19,8% dos apostadores. Use quando a ação tem custo relevante por pessoa: contato humano, oferta com desconto, qualquer coisa em que abordar quem não deveria custa caro.

Corte 480 — o de cobertura. Abordaria 60,5% da base e capturaria 77,8% dos apostadores, mas com precisão de apenas 16,8% — pouco acima dos 13,1% da população. Use quando deixar alguém de fora é o erro caro e a ação é barata: um aviso em aplicativo, um conteúdo educativo. Repare que a precisão quase não melhora sobre o acaso, o que enfraquece bastante o argumento de usar o modelo nesse regime.

A recomendação padrão é 510, com uma ressalva que precisa acompanhar o número: o corte foi calculado na amostra de teste, cuja prevalência é 13,1%. Na safra futura, com 15,9%, o corte equivalente sobe para ~523 — os mesmos +12,7 pontos da recalibração. Cutoff não é constante: ele acompanha a prevalência, e revisá-lo faz parte da rotina de monitoramento.

Módulo 9

Limitações e uso responsável

Um modelo de portfólio que não discute os próprios limites está incompleto. Estas são as limitações reais deste, na ordem em que me preocupariam:

1. Os dados são fictícios. A base foi calibrada a prevalências publicadas, mas as correlações entre variáveis são as que eu impus. Um modelo treinado em dado real teria estrutura diferente, e provavelmente coeficientes menores.

2. O poder preditivo é baixo, e é do problema. KS de 22 significa que o score separa pouco. Nenhuma escolha de algoritmo resolveria isso: o sinal não está nas variáveis socioeconômicas. Trocar a logística por gradient boosting talvez rendesse 1 ou 2 pontos de KS, ao custo da interpretabilidade — mau negócio.

3. Onde estaria o sinal de verdade. Em dado transacional: Pix recorrente para as mesmas contas, horário das transações, saldo médio caindo no fim do mês, uso de crédito rotativo logo após transferências. Foi assim que o Banco Central enxergou o fenômeno — com dado transacional, não com cadastro. Um score socioeconômico é o que se faz quando não se tem o transacional.

4. Discriminação indireta é um risco concreto. As variáveis com maior peso — renda, escolaridade, ocupação, benefício social — são fortemente correlacionadas com raça e classe no Brasil. Um score assim, usado para restringir acesso a produto ou piorar condição de crédito, produziria discriminação indireta mesmo sem nenhuma variável protegida no modelo. Isso não é hipótese: é o mecanismo pelo qual proxies socioeconômicas reproduzem desigualdade. Uso defensável: priorizar ação de proteção, educação financeira, dimensionar exposição de carteira. Uso indefensável: negar crédito, precificar pior ou limitar produto com base nesta pontuação.

5. Causalidade não foi tratada. O modelo mede associação. Deixei de fora, de propósito, variáveis como restritivo e endividamento — o DataSenado aponta que 58% dos apostadores têm dívida vencida há mais de 90 dias, mas isso é provavelmente consequência de apostar, não causa. Colocar essa variável no modelo inflaria as métricas e inverteria a seta causal.

Módulo 10

Próximos modelos do portfólio

Este estudo deixa três continuações naturais, cada uma exercitando uma técnica diferente:

  1. Reject inference. Simular que só se observa o alvo de quem respondeu à pesquisa e recuperar a população completa. É a técnica mais cobrada em crédito e não apareceu aqui.
  2. Modelo de valor, não de propensão. Prever quanto a pessoa aposta, condicional a apostar — regressão gama ou tweedie, com a estrutura de duas partes. O EE119 mostra que o valor cresce com a idade enquanto a propensão cai, ou seja: os sinais se invertem. É um caso raro e ótimo de modelo em duas etapas.
  3. Segmentação antes de modelar. Testar se um modelo por faixa etária bate o modelo único — a mesma pergunta de interação que ficou em aberto no score de visão cliente.
