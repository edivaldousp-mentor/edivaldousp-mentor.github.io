Do Excel ao SQL

Você já sabe filtrar, classificar, usar PROCV e montar tabela dinâmica. Cada uma dessas coisas tem um equivalente exato em SQL, e este curso mostra os dois lado a lado, sobre um banco de 10.000 vendas que você pode abrir e consultar agora.

Módulo 0

Da planilha para a tabela

Você abre uma planilha e vê células. Clica na B7, muda o número, arrasta a fórmula para baixo. No banco de dados nada disso existe, e é a única coisa que precisa mudar na sua cabeça antes da primeira consulta.

Lá a unidade é a linha, não a célula. Você nunca fala com uma célula específica. Você diz quais linhas quer e o que fazer com elas, e o banco se vira com o resto.

As seis diferenças que confundem quem vem do Excel

No ExcelNo banco de dados
A célula B7 existe e tem endereçoNão existe endereço de célula. Existe linha e coluna
As linhas têm ordem (1, 2, 3…)Não existe ordem. Se você quer ordem, pede com ORDER BY
Uma coluna aceita texto e número misturadosCada coluna tem um tipo só: texto, número ou data
A cor da célula pode significar algoNão existe formatação. O banco guarda valor, não aparência
Cada assunto vira uma abaCada assunto vira uma tabela, e as tabelas se ligam por chave
Você arrasta a fórmula até a última linhaA operação já vale para a coluna inteira. Não existe "arrastar"

A que mais pega é a da ordem. No Excel, a linha 5 é a linha 5. No banco, se você não escrever ORDER BY, o resultado vem na ordem que der. Roda de novo e pode vir diferente. Ninguém errou nada: é assim que o banco consegue ler as linhas em paralelo e devolver rápido.

Módulo 4

A ordem em que o SQL pensa

Você escreve a consulta numa ordem. O banco executa em outra. Entender isso resolve de uma vez os dois erros mais comuns de quem está começando.

O SELECT é o quinto passo, não o primeiro. Consequências práticas:

1. Um apelido criado no SELECT não existe no WHERE. Quando o WHERE roda, o SELECT ainda nem aconteceu — o apelido não foi criado. Esta consulta dá erro:

Excel
SELECT valor_venda - custo_total AS margem
FROM vendas
WHERE margem > 1000          ← erro: "no such column: margem"

A saída é repetir a conta no WHERE (ou usar uma subconsulta, no Módulo 10):

SQL
SELECT
    id_venda,
    valor_venda - custo_total AS margem
FROM vendas
WHERE valor_venda - custo_total > 8000
ORDER BY margem DESC
LIMIT 5;
Resultado5 linhas
id_vendamargem
V2024989732.596,76
V2024348932.320,65
V2024693526.882,35
V2024021724.134,76
V2024819023.666,42

2. Mas no ORDER BY o apelido funciona — como você acabou de ver acima. O ORDER BY é o sexto passo, roda depois do SELECT, então o apelido já existe.

3. WHERE filtra linha; HAVING filtra grupo. O WHERE roda antes de agrupar, o HAVING depois. É o Módulo 7 inteiro, e agora você já sabe por quê.

Módulo 6

GROUP BY: a tabela dinâmica

Este é o módulo que faz valer a pena aprender SQL. Tudo que você monta com SOMASES, CONT.SES e tabela dinâmica cabe em três linhas aqui.

Excel
=SOMASES(vendas[valor_venda]; vendas[regiao]; A2)

O SOMASES soma uma coluna filtrando por outra. O GROUP BY faz isso para todos os valores de uma vez, sem você precisar listar as regiões numa coluna auxiliar.

SQL
SELECT
    c.regiao,
    SUM(v.valor_venda) AS receita
FROM vendas v
JOIN clientes c ON v.id_cliente = c.id_cliente
GROUP BY c.regiao
ORDER BY receita DESC;

A regra de ouro do GROUP BY

Tudo que aparece no SELECT e não está dentro de uma função de agregação precisa estar no GROUP BY. Sem exceção. É a regra que o banco usa para saber o que é "a chave do grupo" e o que é "o número calculado".

Agrupar por duas colunas é o mesmo que arrastar dois campos para "Linhas" na tabela dinâmica:

SQL
SELECT
    c.regiao,
    v.canal_venda,
    COUNT(*)                   AS pedidos,
    ROUND(SUM(v.valor_venda))  AS receita
FROM vendas v
JOIN clientes c ON v.id_cliente = c.id_cliente
GROUP BY c.regiao, v.canal_venda
ORDER BY c.regiao, receita DESC
LIMIT 8;

Módulo 7

HAVING: filtrar depois de somar

Na tabela dinâmica você monta o resumo e depois aplica um "Filtro de Valor → É maior que". Esse filtro age sobre o total, não sobre as linhas de origem.

Excel
Tabela Dinâmica → Filtro de Rótulo/Valor → Soma de valor_venda é maior que 4.000.000

Em SQL isso é o HAVING. E aqui está a distinção que confunde todo mundo:

RodaFiltraPode usar função de agregação?
WHEREAntes de agruparLinha a linhaNão
HAVINGDepois de agruparGrupo a grupoSim
SQL
SELECT
    d.nome                      AS vendedor,
    COUNT(*)                    AS pedidos,

A armadilha que infla o seu número

O PROCV sempre traz um resultado: o primeiro que encontrar. O JOIN traz todos. Se a tabela do lado direito tiver o código repetido, cada linha da esquerda vira duas, três, dez linhas, e a soma no fim explode, sem nenhum erro na tela.

Como se proteger, sempre, antes de confiar no resultado: conte as linhas antes e depois. Se mudou e você não esperava que mudasse, tem chave duplicada.

SQL
SELECT
    (SELECT COUNT(*) FROM vendas)                                     AS antes_do_join,
    (SELECT COUNT(*) FROM vendas v JOIN clientes c
        ON v.id_cliente = c.id_cliente)                               AS depois_do_join;
Resultado1 linha
antes_do_joindepois_do_join
10.00010.000

Os dois números batem: 10.000 e 10.000. A chave id_cliente é única na tabela clientes, então o JOIN não multiplicou nada. Faça essa conferência toda vez. É trinta segundos que evitam apresentar uma receita 40% maior do que a real.

A CTE: a mesma coisa, legível

Duas ou três subconsultas aninhadas viram um bolo ilegível. A CTE (WITH ... AS) é a mesma ideia escrita de cima para baixo, com nome — literalmente a sua aba auxiliar, só que declarada antes de usar.

Módulo 12

A tabela dinâmica de verdade

O GROUP BY empilha os grupos em linhas. Para colocar uma dimensão nas colunas — o que a tabela dinâmica faz arrastando um campo para "Colunas" — você combina CASE WHEN com SUM. O truque: o CASE zera tudo que não pertence à coluna, e o SUM soma o resto.

SQL
SELECT
    c.regiao,
    ROUND(SUM(CASE WHEN p.categoria = 'Eletronicos'      THEN v.valor_venda ELSE 0 END)) AS eletronicos,
    ROUND(SUM(CASE WHEN p.categoria = 'Eletrodomesticos' THEN v.valor_venda ELSE 0 END)) AS eletrodom,
    ROUND(SUM(CASE WHEN p.categoria = 'Moveis'           THEN v.valor_venda ELSE 0 END)) AS moveis,
    ROUND(SUM(CASE WHEN p.categoria = 'Vestuario'        THEN v.valor_venda ELSE 0 END)) AS vestuario,
    ROUND(SUM(CASE WHEN p.categoria = 'Esporte e Lazer'  THEN v.valor_venda ELSE 0 END)) AS esporte,
    ROUND(SUM(v.valor_venda))                                                            AS total
FROM vendas v
JOIN clientes c ON v.id_cliente = c.id_cliente
JOIN produtos p ON v.id_produto = p.id_produto
GROUP BY c.regiao
ORDER BY total DESC;

  • SQL para buscar, filtrar, juntar e resumir milhões de linhas. Ele foi feito para isso.
  • Excel para a análise final, o ajuste manual, o gráfico e o que vai para a reunião.
  • Os dois juntos: o SQL devolve 40 linhas resumidas, e é sobre essas 40 que você trabalha.

  4. Qual categoria teve a maior queda de receita de 2024 para 2025? Dica: CASE WHEN para separar os anos numa CTE, e a divisão depois.
  5. Verifique se existe algum produto que nunca foi vendido, e explique como você sabe que a resposta está certa. Dica: LEFT JOIN a partir de produtos e filtrar pelo nulo. Resposta que ninguém encontra é resposta suspeita: confira contando os produtos distintos que aparecem em vendas.
  6. Para cada região, qual foi o mês de maior receita? Dica: ROW_NUMBER com PARTITION BY.
  7. Qual o acumulado de receita mês a mês de 2025, e em que mês ele passa de R$ 15 milhões?

Para onde ir depois

  1. GROUP BY com ROLLUP — subtotais e total geral na mesma consulta.
  2. Índices — por que uma consulta demora 8 segundos e a mesma com índice demora 40 ms.
  3. EXPLAIN — ler o plano de execução e descobrir onde o banco está perdendo tempo.
  4. Views — salvar uma consulta com nome e tratá-la como tabela.
  5. INSERT, UPDATE, DELETE — este curso só leu dados; escrever é outro capítulo, e o UPDATE sem WHERE é a forma clássica de estragar a segunda-feira.
